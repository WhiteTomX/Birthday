<task type="auto">
  <name>Task 2: Create rsvp Pages Function with name injection</name>
  <files>functions/rsvp/index.js</files>
  <action>
    Create `functions/rsvp/index.js`. Cloudflare Pages Functions placed at
    `functions/rsvp/index.js` intercept GET requests to `/rsvp/` — this replaces
    the static file serving for that route (the static `public/rsvp/index.html`
    file remains untouched as the HTML source).

    The function must:

    1. Only handle GET requests; pass through everything else via `context.next()`.
    2. Read the static HTML via `context.env.ASSETS.fetch(context.request)` — this
       is the standard Cloudflare Pages pattern to fetch the static asset from the
       Pages asset binding without an extra network round-trip.
    3. Read `X-Host-Ref` header from the incoming request (injected by middleware).
       Parse it as an integer (0 or 1). If absent or unparseable, default to 0.
    4. Pick the name: if `hostRef === 0`, use `context.env.INVITE_NAME__0`; if
       `hostRef === 1`, use `context.env.INVITE_NAME__1`. Trim whitespace. If the
       result is falsy/empty, fall back to the string `"Wir"`.
    5. Get the HTML body as text from the asset response.
    6. Replace ONLY the first occurrence of `>Wir werden 30<` with
       `>${name} werden 30<`. Use `String.prototype.replace()` (not replaceAll) with
       a literal string — this ensures only the first match in the paragraph is
       replaced and avoids regex complexity. The exact string to match is
       `>Wir werden 30<` (with angle-brackets to avoid touching any other "Wir" that
       may appear elsewhere in the document).
    7. Return a new Response with the modified HTML, preserving the Content-Type
       header from the asset response (`text/html; charset=utf-8`) and adding
       `Cache-Control: no-store` so personalised pages are never cached by CDN or browser.

    Export the handler as a named export:
      export async function onRequestGet(context) { ... }

    Do NOT use `export default` — Pages Functions use named HTTP-method exports.
  </action>

  </verify>
