## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAFAFA` | Page background, form background |
| Secondary (30%) | `#F0F0F0` | Card/container surface, input backgrounds, disabled stepper button background |
| Accent (10%) | `#4D7C8A` | See reserved list below |
| Text primary | `#1A1A1A` | All body text, headings, labels |
| Text muted | `#6B6B6B` | Placeholder text, optional field hint, deadline caption |
| Border | `#D4D4D4` | Input borders, stepper border, form dividers |
| Destructive | `#DC2626` | Inline validation error messages only |

**Accent (`#4D7C8A`) reserved for:**
1. Primary CTA button ("Anmelden") — background fill
2. Stepper "+" and "−" buttons — background fill
3. Keyboard focus ring on all interactive elements (2px outline, 2px offset)

Accent is a muted teal-slate: contemporary and calm, avoids stark contrast while remaining accessible against `#FAFAFA` at 16px+ (contrast ratio ≈ 4.6:1 on white — meets WCAG AA for normal text).

> Source: D-01, D-02 (agent-chosen palette). Destructive color from prompt spec.

## Interaction & Validation

### Client-Side Validation (RSVP-04)

Validation fires on submit attempt. Fields are not validated on blur (reduces friction).

| Condition | Behaviour |
|-----------|-----------|
| Name field empty on submit | Show inline error below field, apply error border, focus field |
| All required fields valid | Allow form submission (Phase 3 wires action/method) |
| Stepper already pre-filled at 1 | No validation error needed — cannot be blank |

### Error Message Placement

- Rendered as `<span role="alert">` immediately below the invalid field
- Color: `#DC2626` (Destructive)
- Size: Label (14px/400)
- Appears on submit; removed as soon as field becomes valid (on `input` event)

### Inline Error Copy (German)

| Field | Error message |
|-------|--------------|
| Name (empty) | "Bitte gib deinen Namen ein." |
| Attendee count (fallback, if value somehow 0) | "Bitte gib mindestens 1 Person an." |

### Stepper Interaction

- Click `−`: decrement value by 1; if value reaches 1, disable `−` button
- Click `+`: increment value by 1; if value reaches 10, disable `+` button
- Value display updates immediately on each click
- Hidden input kept in sync with displayed value

### Form Action Stub

The `<form>` element's `action` and `method` attributes are left as Phase 3 hooks:

```html
<!-- Phase 3: set action="/api/rsvp" method="POST" -->
<form id="rsvp-form" action="#" method="get">
```

## Accessibility Notes

- All form inputs have an associated `<label>` (explicit `for`/`id` pairing)
- Error messages use `role="alert"` so screen readers announce them immediately
- Focus ring: 2px solid `#4D7C8A`, 2px offset — visible on all interactive elements
- Stepper buttons have `aria-label` attributes: `aria-label="Weniger"` and `aria-label="Mehr"`
- Stepper count display uses `<output>` element or `aria-live="polite"` region
- Color contrast: text `#1A1A1A` on `#FAFAFA` ≈ 19:1 (AAA); accent `#4D7C8A` on white ≈ 4.6:1 (AA)
- Destructive `#DC2626` on white ≈ 4.8:1 (AA for normal text at 14px/600)
