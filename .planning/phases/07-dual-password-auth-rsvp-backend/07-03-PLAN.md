<objective>
Make the RSVP API store the host index that the middleware established for the request.

Purpose: Every RSVP must record which host's circle the guest belongs to. Output: `functions/api/rsvp.js` reads and validates `X-Host-Ref`, then includes `host_ref` as the 6th column in the INSERT.
</objective>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| Client spoofing X-Host-Ref to misattribute a guest | MED | Middleware (07-02) always overwrites `X-Host-Ref` on the forwarded request after authenticating, so a client-supplied value cannot reach this handler. This API additionally validates `hostRef` is strictly `0` or `1` and rejects anything else with 400 (D-06). |
| Missing host context (request bypassing middleware) inserting NULL/garbage host_ref | MED | The handler returns 400 when `X-Host-Ref` is absent or not `0`/`1`, before any DB write. This is the application-level NOT-NULL guarantee for new records (D-06), since the column itself is nullable for backfill reasons. |
| SQL injection via host_ref or other fields | LOW | All values are passed through D1 prepared-statement `.bind(...)` parameters — no string interpolation into SQL. `hostRef` is a parsed integer (`0` or `1`) before binding. |
| Credential leakage | HIGH | This API never reads the Authorization header or any password; it only reads the derived `X-Host-Ref` index. No password value is logged or stored. |
</threat_model>
