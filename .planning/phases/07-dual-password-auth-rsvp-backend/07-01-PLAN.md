| Threat | Severity | Mitigation |
|--------|----------|------------|
| Migration applied to wrong/production DB destroying data | MED | Migration uses additive `ALTER TABLE ADD COLUMN` only — no DROP/destructive ops. Backfill is an idempotent `UPDATE ... WHERE host_ref IS NULL`. Verify locally against `--local` D1 before any remote apply. |
| Re-running migration corrupts data (non-idempotent ALTER) | LOW | Wrangler's migration tracking table prevents re-application of an already-applied numbered migration. The backfill UPDATE is itself idempotent (only touches NULL rows). |
| Schema drift between `schema.sql` and live DB causing silent column mismatch | LOW | D-03 retires `schema.sql` as source of truth; `migrations/` is canonical. No code reads `schema.sql` at runtime. |
</threat_model>
