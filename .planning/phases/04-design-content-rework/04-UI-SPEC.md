## "Save the Date" — Content Placement (LOCKED)

This is the highest-priority change in Phase 4. "Save the Date" **must appear as visible on-page content** — not only in `<title>`.

**Required DOM change in `public/index.html`:**

Add a `<p class="eyebrow">Save the Date</p>` element as the **first child** of `.save-the-date`, directly above the `<h1>`:

```html
<section class="save-the-date">
  <p class="eyebrow">Save the Date</p>   <!-- NEW — locked requirement -->
  <h1>5. Dezember</h1>
  <p>„Moin, ..."</p>
  <p class="deadline">Bitte bis Ende Mai anmelden.</p>
</section>
```

The eyebrow renders as a pill-style badge in festive gold. It is not decorative — it is primary content.

## Spacing Scale

Declared values (4px grid):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, eyebrow badge internal padding (vertical) |
| sm | 8px | Gap between eyebrow badge and h1; label-to-input gap |
| md | 16px | Body paragraph bottom margin; horizontal input padding |
| lg | 24px | Between form fields; h1 bottom margin |
| xl | 32px | Form card internal padding; submit button top margin |
| 2xl | 48px | — (reserved) |
| 3xl | 64px | — (reserved) |

**Phase 4 spacing overrides** (changes from Phase 2 baseline):

| Property | Old Value | New Value | Reason |
|----------|-----------|-----------|--------|
| `body` padding (mobile) | `64px 16px` | `80px 16px` | More breathable, invitation feel |
| `body` padding (≥600px) | `64px 32px` | `80px 32px` | Consistent increase |
| `.container` max-width | `560px` | `600px` | Wider canvas for celebration content |
| `.save-the-date` margin-bottom | `48px` | `56px` | Extra breathing room before decorative divider |
| `.save-the-date h1` margin-bottom | `16px` | `24px` | Let the large date number breathe |
| `--radius` | `6px` | `8px` | Softer, friendlier corners throughout |

**Form card — new visual layer:**
`.rsvp-section` becomes a card:
```css
.rsvp-section {
  background-color: var(--surface);
  border-radius: 12px;
  padding: 32px;          /* xl */
}
```
This is a new layout element not in Phase 2.

Exceptions to 4px grid: none.

## Decorative Divider — Visual Contract

A single decorative divider appears between `.save-the-date` and `.rsvp-section`.
Implemented as an empty `<div class="divider" aria-hidden="true"></div>` in the HTML,
or as a CSS `::before` / `::after` on `.rsvp-section`.

Preferred approach — add to HTML between the two sections:
```html
</section>

<div class="divider" aria-hidden="true"></div>

<section class="rsvp-section">
```

CSS:
```css
.divider {
  text-align: center;
  margin: 0 0 32px;    /* xl gap before RSVP card */
  color: var(--festive);
  font-size: 20px;
  letter-spacing: 0.5em;
}
.divider::before {
  content: "✦  ✦  ✦";
}
```

Ich update die Seite, wenn ich mehr weiß und versuche euch zu informieren. Aber ich verspreche nichts :)."` | Unchanged from Phase 2 |

## Interaction Contract

All interaction behaviour from Phase 2 and Phase 3 is preserved without change:

| Interaction | Behaviour | Change in Phase 4 |
|-------------|-----------|-------------------|
| Name field — empty submit | `.error` class + `visible` on error span | No change |
| Name field — typing after error | Error clears on `input` event | No change |
| Stepper −/+ buttons | Decrement/increment count 1–10; min disables − | No change (color updates to new `--accent`) |
| Submit loading | Button disabled + text `…` | No change |
| Submit success | Form replaced with `<p class="success-msg">` | `.success-msg` needs new CSS to match festive palette |
| Submit error | Error `<p>` appended below form | No change in behaviour (color updates to `--error`) |
| Focus ring | `outline: 2px solid var(--accent)` on `:focus-visible` | Updates to new `--accent` (#C0395A) automatically |

**Success message styling** (new CSS required — this element is created by JS):
```css
.success-msg {
  font-size: 24px;
  font-weight: 700;
  line-height: 1.4;
  color: var(--accent);
  text-align: center;
  padding: 24px 0;
}
```
