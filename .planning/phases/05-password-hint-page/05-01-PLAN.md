<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Cloudflare Edge | Unauthenticated request; the 401 response body is publicly visible |
| Edge → Origin | `onRequest` runs before any asset is served; no secrets flow to unauthenticated callers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | `unauthorizedResponse()` HTML body | accept | The hint page is intentionally public — it contains the riddle, not the answer. No credentials, PII, or internal paths are present in the response body. |
| T-05-02 | Information Disclosure | `Cache-Control` header | mitigate | Set `Cache-Control: no-store` on every 401 response (per D-08) so the riddle page is never served from a shared cache to a user who subsequently authenticates. |
| T-05-03 | Spoofing | `WWW-Authenticate` header | accept | Header is preserved; browsers show the native credential dialog. No custom login form means no phishing surface introduced by this change. |
| T-05-04 | Denial of Service | Repeated unauthenticated requests | accept | Cloudflare's edge rate-limiting applies at the infrastructure layer; no application-level mitigation needed for a static response. |
</threat_model>
