## Overview

Guests who need the password now see a warm, festive HTML page with a German birthday riddle instead of a blank browser screen. The root URL `/` serves a public hint page (no auth dialog), and wrong/cancelled credentials at `/rsvp/` return the riddle as the 401 body. The RSVP form was moved to `/rsvp/` as part of this restructure.

## Milestone Summary

**Key Decisions:**

- Route restructure: RSVP page moved to `/rsvp/`, root `/` becomes the public hint page — separates auth-gated content from public landing
- Inline CSS in 401 body: not used — `style.css` publicly excluded from auth so it can be linked from 401 response
- `Cache-Control: no-store` on 401: prevents Cloudflare edge caching the 401 and trapping authenticated guests
- JS auto-redirect on hint page: `public/index.html` auto-navigates to `/rsvp/` so authenticated guests bypass the hint page seamlessly

**Issues Resolved:**

- Blank browser screen / no-credential UX — replaced with warm riddle page
- Auth-gated CSS for 401 body — resolved by adding `/style.css` to public exclusion list

**Issues Deferred:**

- RSVP form `action="#" method="get"` fallback (Phase 2 legacy, safe — JS handles submission)
- No VERIFICATION.md for Phase 5 — documentation gap, all requirements verified in SUMMARY.md and audit
