## v1.0 Requirements — RSVP Site (Shipped)

All 12 requirements implemented and verified. Checkboxes reflect final state at milestone close.

### Access Control

- [x] **AUTH-01**: User can access the site after entering the correct password (HTTP Basic Auth, Worker-enforced)
  - *Outcome: Validated ✅ — `functions/_middleware.js` onRequest + `env.SITE_PASSWORD` → `context.next()`*
- [x] **AUTH-02**: Unauthenticated requests are rejected with a 401 response and a browser login prompt
  - *Outcome: Validated ✅ — `unauthorized()` returns `401 + WWW-Authenticate: Basic realm="Birthday Site"`*

### RSVP Collection

- [x] **RSVP-01**: Guest can submit their name via the RSVP form
  - *Outcome: Validated ✅ — `<input type="text" id="name">` wired to payload.name, stored in D1 name column*
- [x] **RSVP-02**: Guest can select a preferred contact method (WhatsApp, Telegram, Signal, Discord, Matrix, SMS, Threema)
  - *Outcome: Validated ✅ — `<select id="contact">` with all 7 options*
- [x] **RSVP-03**: Guest can specify how many people they are bringing (plus-ones, including zero)
  - *Outcome: Validated ✅ (with note) — stepper min=1 ("1 = just me" / Anzahl der Personen = total); spec "including zero" was minor ambiguity*
- [x] **RSVP-04**: Form validates required fields before submission and shows inline error messages
  - *Outcome: Validated ✅ — empty name → `showNameError()` inline German error, no form navigation*
- [x] **RSVP-05**: Submission is sent to a Cloudflare Worker endpoint
  - *Outcome: Validated ✅ — `fetch('/api/rsvp', { method: 'POST' })` in script.js; Worker at `functions/api/rsvp.js`*
- [x] **RSVP-06**: Each RSVP is stored as a new record with a unique ID in Cloudflare D1 (no overwrites)
  - *Outcome: Validated ✅ — `crypto.randomUUID()` PK, INSERT with no ON CONFLICT; two submissions → two rows confirmed*
- [x] **RSVP-07**: Guest sees a success confirmation message (in German) after submitting
  - *Outcome: Validated ✅ — `p.textContent = 'Danke, {name}! Deine Anmeldung wurde gespeichert.'` on `res.ok`*

### Presentation

- [x] **PAGE-01**: Site displays a save-the-date page with event description and date (5 December)
  - *Outcome: Validated ✅ — `<section class="save-the-date">`, `<p class="eyebrow">Save the Date</p>`, `<h1>5. Dezember</h1>`, description paragraph*
- [x] **PAGE-02**: All UI text is in German
  - *Outcome: Validated ✅ — `lang="de"`, all labels/errors/buttons in German; "Save the Date" intentionally English as recognized international phrase*
- [x] **PAGE-03**: Site is responsive and usable on mobile and desktop
  - *Outcome: Validated ✅ — viewport meta tag, max-width container, padding breakpoints, `@media (max-width: 599px)` h1 scaling*

## Notes on Changed Requirements

- **RSVP-03** ("including zero"): Implementation uses stepper with MIN=1 interpreting "1 = just me (total people attending)". The "plus-ones" framing in the spec vs "Anzahl der Personen" (number of people) label created a minor ambiguity. Accepted as-is for v1.0 — clarify intent in v2.0 if needed.
- **PAGE-02** ("All UI in German"): The "Save the Date" eyebrow badge added in Phase 4 is intentionally English as it is a universally recognized international phrase. All other UI text remains German.
